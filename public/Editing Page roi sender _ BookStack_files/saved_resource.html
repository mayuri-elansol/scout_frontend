This document explains how the Realtime Streaming + AI Detection microservice works, in very simple language, step‑by‑step.
It is written for beginners and is suitable to paste directly into BookStack.

1️⃣ What is this Microservice?

This microservice is responsible for:

  • 📥 Receiving AI detection messages from Kafka

  • 🌐 Sending those messages to the frontend in real‑time using WebSockets

  • 🎥 (Optional) Sending live video frames to the frontend

  • 🎯 Allowing the frontend to draw ROI (bounding boxes) only for the selected camera & use‑case

In short:

Kafka → Microservice → WebSocket → Frontend (Canvas Rendering)

4️⃣ Backend – Kafka Consumer (KafkaService)

📄 File: kafka.service.ts

What does this file do?

  • Connects to Kafka broker

  • Subscribes to AI topics like:

    • safety.ppe

    • safety.fire

  • Listens for messages

  • Sends received data to WebSocket gateway

Simplified Flow

Kafka Message → KafkaService → RealtimeFrameGateway

Important Code Explanation

1. Kafka Connection

const kafka = new Kafka({
  clientId: 'scout-realtime-service',
  brokers: ['192.168.0.56:9093'],
});

  • Connects to Kafka broker

  • clientId identifies this service

2. Consumer Group

this.consumer = kafka.consumer({ groupId: 'scout-group' });

  • Ensures load balancing if multiple services run

3. Topic Subscription

await this.consumer.subscribe({ topic: 'safety.ppe' });
await this.consumer.subscribe({ topic: 'safety.fire' });

  • Each topic represents a use‑case

4. Message Handling

const data = JSON.parse(message.value.toString());
this.realtimeGateway.broadcastDetection(topic, data);

  • Parses message

  • Forwards it to WebSocket clients

5️⃣ Backend – WebSocket Gateway

📄 File: realtime.gateway.ts

What does this file do?

  • Manages WebSocket connections

  • Tracks connected clients

  • Sends Kafka messages to frontend

WebSocket Lifecycle

Client Connects → Added to Set
Client Disconnects → Removed from Set
Kafka Message → Broadcast to Clients

Key Concepts

WebSocket Initialization

@WebSocketGateway({
  cors: { origin: '*' },
  transports: ['websocket'],
})

  • Enables WebSocket

  • Allows frontend connection

Client Tracking

private clients = new Set<string>();

  • Keeps list of active users

Broadcasting Data

this.server.emit(topic, data);

  • Sends message to all connected clients

  • Event name = Kafka topic (example: safety.ppe)

6️⃣ Backend Startup

📄 File: main.ts

await app.listen(4006, '0.0.0.0');

  • Microservice runs on port 4006

  • Accessible from frontend & other services

7️⃣ Frontend – WebSocket Hook

📄 File: useRealtimeSocket.ts

Why this hook?

  • Central place to manage WebSocket logic

  • Automatically connects & disconnects

  • Subscribes to:

    • Detection events (PPE, Fire, etc.)

    • Live frames (optional)

Flow

Component → useRealtimeSocket → Socket.IO → Backend

Important Logic

socket.on(options.topic, options.onData);

  • Listens to selected use‑case only

socket.close();

  • Prevents memory leaks

8️⃣ Frontend – Live Video Player

📄 File: LiveVideoPlayer.tsx

What does this component do?

  • Shows live camera feed

  • Draws AI detections on top of video

  • Filters data by:

    • Selected Camera

    • Selected Use‑Case

9️⃣ Camera & Use‑Case Filtering (Very Important)

Why filtering is needed?

Kafka sends detections for ALL cameras, but frontend must:

✅ Draw ROI only for selected camera
❌ Ignore other cameras

Filtering Logic

if (
  data.camera_id !== selectedCamera ||
  data.use_case !== selectedUseCaseKafkaKey
) return;

This ensures:

🎯 ROI is drawn only on the correct live stream

🔟 Canvas Drawing Flow

Step‑by‑Step

1. Frame arrives (optional)
2. Frame drawn on canvas
3. Detection arrives
4. Bounding boxes drawn on same canvas

ROI Drawing

  • Uses bbox: { x1, y1, x2, y2 }

  • Draws rectangle + label

ctx.strokeRect(x1, y1, x2 - x1, y2 - y1);
